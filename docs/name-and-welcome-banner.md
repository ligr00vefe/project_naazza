# 이름과 홈 환영 배너 · 성별 필수 입력

## 동작

- 더보기 → 내 정보에 이름 입력란을 추가했다. 이름은 선택 입력이며 앞뒤 공백을 제거하고 30자 이내로 검증한다. 빈 값으로 저장하면 이름을 삭제한다.
- 이름은 로그인 아이디와 별개로 Supabase Auth의 `display_name` 사용자 메타데이터에 저장한다. 기존 생년월일·성별·생애주기 저장 경로를 사용하며 이름을 전달하지 않은 업데이트에서는 기존 이름을 보존한다. 이름·성별은 권한 판정에 사용하지 않는다.
- 홈 상단 배너에 `OOO님 환영합니다.`를 표시한다. 이름이 없으면 `오늘도 반가워요!`를 표시하고 로그인 아이디를 이름으로 대체하지 않는다.
- 건강 응원 문구 8개 중 홈 진입 시 하나를 고른다. 같은 배너가 다시 빌드되거나 이름이 갱신되어도 문구를 유지한다. 다음 홈 진입에서는 직전 문구를 제외하고 고른다. 타이머·추가 AI 호출·추가 서버 요청은 없다.
- 기본 글자 크기에서 약 100px 높이의 작은 민트 카드와 64×72px 캐릭터를 사용한다. 긴 이름은 두 줄까지만 표시하며 큰 글자에서는 높이가 자연스럽게 늘어난다.

## 성별

- `나중에 선택`을 제거하고 남성·여성 두 선택지만 제공한다. 임의의 기본값은 넣지 않는다.
- 회원가입 화면에 필수 성별 선택을 추가했다. 로그인 화면에는 성별 필드를 표시하지 않는다.
- `username-signup` 함수도 `nutrition_sex` 누락·잘못된 값을 400으로 거절한다. 유효한 값은 계정 생성 시 저장한다. 기존 인증 토큰·권한·아이디 동작은 바꾸지 않는다.
- 가입 후 맞춤 설정 완료와 내 정보 저장도 성별 선택을 검증한다. 성별이 없는 기존 회원의 로그인이나 기록 조회를 차단하지 않으며, 프로필을 저장할 때 성별을 선택하도록 안내한다.
- 생년월일과 이름은 여전히 선택 입력이다. 여성의 추가 영양 기준 선택도 유지한다.

## 검증

- 프로필 이름 정규화·길이·줄바꿈, 이름 삭제, 성별 누락, 이름과 아이디 분리, 재로그인 보존을 확인한다.
- 회원가입·프로필 화면 필수 검증, 작은 화면과 글자 2배, 배너 높이, 일반 재빌드 시 문구 유지와 다음 진입 시 문구 변경을 테스트한다.
- 운영 서버에서 임시 QA 계정으로 성별 없는 가입 거절과 이름 저장·재로그인·이름 삭제를 검증했다. 로그인 아이디와 역할 유지도 확인했다. QA 세션 종료 후 해당 계정을 삭제하고 남은 테스트 계정이 0개임을 확인했다.
- 새 회원가입 함수를 운영 프로젝트에 배포했다. 새 필수 입력을 보내는 최신 앱에서 회원가입해야 한다.
