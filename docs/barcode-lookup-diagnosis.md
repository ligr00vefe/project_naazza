# 바코드 조회 점검 (2026-10-21)

- 앱의 `product-barcode`는 Open Food Facts의 바코드 일치 조회만 사용한다. 사진 분석 및 국내 공공 영양정보 검색과는 다른 경로다. 바코드 번호만으로 국내 공공데이터의 제품명을 추측해 자동 연결하지 않는다.
- 사용자 제공 `8801056251154`: 체크디지트 정상. 원본 API가 HTTP 404 / status 0 / product not found를 반환했다. 운영 서버에 로그인한 Flutter SDK 경로에서도 `product: null`을 확인했다. 번호 형식 오류나 함수 미배포가 원인은 아니다.
- 비교용 `5449000000996`: 등록된 콜라가 반환된다. 기존 변환은 ml를 무시하고 100g으로 처리했다. 수정 후 실서버·Flutter 변환 결과는 330ml, 139.92kcal다. 이 수치는 비교용 다른 제품의 데이터이며 사용자 제품에 대입하지 않는다.
- 기존 변환은 열량·탄수화물·단백질·지방·나트륨 중 하나라도 없으면 제품 전체를 버렸다. 열량이 확인되면 제품을 반환하고, 없는 다른 영양소는 원본 메타데이터에 null로 유지한다. 실제 0kcal와 미등록은 구분한다.
- 전체 용량 또는 1회 제공량이 g/ml로 확인되면 단위를 보존한다. 둘 다 없으면 기준량 100g 및 용량 확인 필요 안내를 표시한다. 포장 용량이 확인된 것처럼 숨기지 않는다.
- 앱 바코드 요청은 18초 제한을 적용하고, 미등록·열량 미등록·연결 오류를 다른 안내로 표현한다. 자동 재시도나 사용자 요청 차단은 추가하지 않는다.
- 기존 미등록 바코드를 검색 가능하게 만드는 국내 바코드 연계나 별도 상품 DB는 이번 수정에 포함되지 않는다.
- 미등록·조회 실패 안내에 `제품 사진으로 계속`을 표시한다. 탭하면 스캐너 화면을 사진 기록 화면으로 교체하고 카메라를 한 번 연다. 사진 촬영 후 기존 제품 인식 → `product-nutrition` 국내 공공데이터 검색 → 사용자 일치 확인 흐름을 사용한다. 먹은 날짜·시각을 유지한다.
- 촬영을 취소해도 사진 화면에서 다시 촬영하거나 앨범을 선택할 수 있다. 공공데이터에서도 찾지 못하면 촬영한 사진과 읽은 제품명을 유지한 직접 입력 경로를 제공한다. 자동 반복 요청·자동 저장을 하지 않는다.
- 시도했던 바코드는 화면 전환 정보로만 전달하며, 사진으로 검색한 후보와 바코드가 검증되어 연결된 것으로 저장하지 않는다.
- 현재 조회처의 범위를 설명하는 문구를 추가했다. `2018년 이전 제품만 인식 가능`은 현재 사용하는 Open Food Facts의 제한이 아니므로 표시하지 않는다.

검증: Node 바코드 체크디지트·단위·누락 영양소·0kcal 변환, Flutter 저장 시 ml 및 null 보존, 소분 계산, 서버 오류 처리, 운영 로그인 조회. 임시 QA 계정은 세션 종료 후 삭제한다.

- [영양 필드 설명](https://github.com/openfoodfacts/openfoodfacts-server/blob/main/html/data-fields.txt): `_100g` 필드는 식품 100g 또는 음료 100ml 기준이다.
