# 증상·컨디션·선택 음식 관찰 (2026-10-20)

## 화면

- 인사이트 첫 영역에 월별/연도별 기간 선택, 증상 강도 차트, 음주 전후 변화, 선택 음식 관찰을 배치한다. 영양 섭취·공복 시간·물 배너는 유지한다.
- 기본 증상은 음식 선택과 독립적으로 표시한다. 복통·복부팽만·피로·메스꺼움·설사별로 월 화면은 날짜별, 연 화면은 월별 최대 **기록 강도**를 표시한다. 여러 시점의 기록은 셀을 눌러 확인한다.
- 강도는 사용자 입력 1/2/3이며 임의 점수로 환산하지 않는다. 강도 없는 기존 기록은 점, 명시적 정상/해당 증상 종료는 체크, 미기록은 대시로 표시한다. 하루/한 달 전체가 무증상이었다는 뜻은 아니다.
- 항목명은 고정하고 시간축은 가로로 스크롤한다. 최근 기록 시점을 먼저 보여준다.
- 음주 및 선택 음식은 당일/다음날의 명시적인 새 증상 시작을 막대로 비교한다. 사례별 상세는 섭취·증상 시작·지속·종료 시점을 시간축과 원본 목록으로 보여준다. 음주의 주종/용량도 원본 상세에서 확인/수정한다.
- 상세 화면에서 원본을 수정하면 복귀 시 관찰 결과를 다시 계산한다.

## 관찰 규칙

- 모든 음식에 자동으로 원인 순위를 붙이던 로직과 임의의 3사례/2일 반복 기준을 제거했다. 다음 식사 전 첫 기록만 연결하던 제한도 제거했다.
- 관찰할 음식과 포함할 기록 이름/증상은 사용자가 선택한다. 공백/영문 대소문자만 정규화하며 브랜드·맛·상품명은 자동 병합하지 않는다. 이름 묶음은 영양정보를 합치거나 과거 영양값을 재사용하는 기능이 아니다.
- 음식별 섭취 시간은 기록의 실제 식사 시각을 사용한다. 같은 시각·끼니의 중복 항목은 한 관찰로 묶고 시각이 다르면 별도로 유지한다.
- 탐색 범위는 기기 현지 시각의 섭취일부터 다음날 24시 전까지다. 의학적 반응 시간 기준이 아니다. 식사 중/직후도 포함하며 다음 식사 때문에 끊지 않는다.
- 증상 시작 시각이 섭취 이전이면 새 증상으로 세지 않는다. 연결한 동일 증상의 지속·종료는 당일/다음날 범위를 넘어도 표시한다. 연결이 없는 미기록 구간의 지속을 추정하지 않는다.
- 같은 증상 묶음의 새 발생은 한 번만 집계한다. 여러 섭취 범위에 겹치면 가장 이른 해당 섭취를 기준으로 당일/다음날을 분류한다. 서로 다른 증상은 각각 집계한다. 상세에서는 중복되는 원본이 그대로 확인된다.
- 지속 사례 수, 상태 미확인 사례 수, 시작 미확인 기록 수는 별도이며 서로 배타적이거나 합계가 총 섭취 수인 지표가 아니다. 발생 확률/원인 판정/진단을 제공하지 않는다.
- 다른 음식과 음주도 함께 볼 수 있으며 연결된 증상이 며칠 이어지면 그 기간의 다른 섭취도 확인할 수 있다.
- 기존 컨디션/배변 기록은 시작 시점을 새로 추정하지 않는다. 기존 자료도 차트와 상세에서 보이지만 새 발생 집계에는 넣지 않는다. 정상·건너뛰기 응답의 오래된 증상 필드는 무시한다.

## 입력·저장

- 컨디션 입력에서 증상마다 `시작 시점 모름 / 새로 시작 / 이어지는 중 / 끝났어요`, 선택 강도, 새 시작 시각 또는 이전 증상 연결을 입력한다.
- 새 시작은 기본 기록 시각에서 수정 가능하다. 시작 시각은 기록 시각 이후일 수 없고, 미래 기록도 저장하지 않는다. 지속/종료 연결은 같은 증상의 유효한 이전 시작을 선택한다. 이전 기록이 없다면 연결 없이 그 시점 상태만 남길 수 있다.
- 증상 묶음 ID는 원본 수정 후에도 유지한다. 종료를 전체 정상으로 변환하지 않는다. 기존 기록을 수정만 해도 새 발생으로 바뀌지 않는다.
- `condition_logs.details.symptom_events`에 증상별 상태/시작/묶음 ID/강도를 보관한다. 기존 소유자별 RLS를 유지한다.
- `food_observation_preferences`는 사용자당 한 행으로 음식 목록을 보관한다. JWT/로그인 메타데이터와 분리했다. SELECT/INSERT/UPDATE/DELETE 모두 본인 소유자 정책을 적용하고 익명 접근은 허용하지 않는다. 계정 삭제 시 같이 제거한다.
- 목록 편집/삭제는 원본 식사·증상 기록에 영향을 주지 않는다. 저장 실패 시 편집 내용은 유지한다. 다른 계정으로 전환하면 해당 계정 목록을 다시 불러온다.
- 추가 AI/식품 API 호출이나 새 API 키는 필요 없다. 관찰 차트는 기존 사용자 기록으로 기기에서 계산한다.

## 검증

- 즉시 발생, 다음날 23시, 경계 밖 기록, 여러 증상, 3일 지속/종료, 섭취 전 시작, 결측/건너뛰기/기존 기록, 함께 먹은 음식, 동일 시각 묶음, 미래 제외, 사용자별 설정 분리를 테스트한다.
- 320px 화면에서 기본/2배 글자, 그래프와 원본 이동, 설정 저장 실패 복구, 기존 증상 수정 시 묶음 ID 유지와 지속/종료 저장을 위젯 테스트한다.
- 실제 Supabase 임시 계정으로 목록과 컨디션의 저장/조회/수정/삭제를 검증한다. 테스트 계정은 로그아웃 후 제거한다.
- `artifacts/food-observation-implemented-preview.png`는 실제 위젯을 가상 기록으로 렌더링한 검토용 이미지다.

이 문서는 `health-patterns-and-past-records.md`의 이전 인사이트 연결 방식을 대체한다. 캘린더의 과거 날짜 기록 기능은 그대로 유지한다.
