# 상태 중심 인사이트와 과거 날짜 기록 (2026-10-20)

> 인사이트 부분의 24시간 첫 기록 연결 및 반복 항목 로직은 이후 제거했다. 현재 구현은 [증상·컨디션·선택 음식 관찰](food-and-condition-observations.md)을 따른다. 아래 인사이트 부분은 이전 변경 이력이며 캘린더 기능은 유지된다.

## 인사이트 변경
- 기간별 기록, 기록 횟수 그래프, 기록 연속성/이용일수, 기존 기록 요약과 '나짜의 관찰' UI를 제거했다.
- 영양 섭취 비교, 공복 시간 분석, 물 배너는 유지한다.
- '컨디션 변화': 최근 30일의 명시적으로 확인된 최신/직전 컨디션과 배변 상태를 시각과 함께 제시한다. 기록 사이 상태를 연속 추적한 것으로 해석하지 않는다.
- '음식·음주 이후의 상태': 같은 끼니의 시간 묶음 또는 음주 기록 뒤 24시간 안의 첫 명시적 컨디션/배변을 연결한다. 식사는 다음 식사 전까지만, 음주는 다음 음주 전까지만 연결한다. 24시간은 기록 탐색 창이며 의학적 반응 시간이나 원인 판정 기준이 아니다.
- 식사/음주 전 24시간 안에 명시적 이전 상태가 있으면 함께 보여준다. 이전 상태가 없으면 전후 변화는 단정하지 않는다.
- 이상 없음/증상 응답만 사용한다. 건너뛰기, 항목 없는 증상, 응답 없는 식사/음주, 미래 기록은 분모에도 넣지 않는다. 이전 배변 기록에서 누락된 혈변/통증 필드를 정상으로 추정하지 않는다.
- 음식명은 해당 시간 묶음에 기록한 음식명 그대로 사용하며 원재료별 함량이나 식품 분류를 추측하지 않는다.
- 반복 항목은 같은 음식명(또는 음주)과 같은 상태 종류에서 연결 사례 3개 이상, 같은 증상이 2개 이상의 서로 다른 날짜에서 기록된 경우만 표시한다. 연결 사례 수와 해당 증상 사례 수를 보여주며 통계적 유의성/인과성/진단은 주장하지 않는다. 함께 먹은 다른 음식과 음주 등의 영향을 분리하지 못한다는 안내를 제공한다.
- 각 사례/반복 항목의 근거는 바텀시트에서 확인하고 원본 기록 상세/수정으로 이동할 수 있다.
- 무료 API/AI/DB 테이블/서버 함수를 추가하지 않는다. 기존 소유자별 기록을 기기에서 계산한다.

## 캘린더의 날짜별 새 기록
- 오늘/과거 날짜 선택 시 '이 날짜에 기록하기'를 표시한다. 미래 날짜는 추가 버튼을 표시하지 않는다.
- 날짜 + 현재 시각을 초기값으로 기록 허브/사진/직접 입력/바코드/컨디션/배변/음주/내원 화면으로 전달한다. 사용자가 시각을 변경할 수 있다.
- 음주와 컨디션 입력에도 날짜·시간 필드를 추가했다. 현재 시각으로 강제 저장하던 코드를 수정했다.
- 이미 등록된 기록 수정 시에는 기존 기록 시각이 우선이다. 사진의 직접 입력 전환과 바코드 대체 경로에서도 입력 시각이 유지된다.
- 공통 날짜 선택기의 과거 2000년 제한을 제거하고 DateTime의 양의 연도 범위를 사용한다. 내원의 다음 일정은 기존 미래 예약 입력을 유지한다.
- 캘린더에서 시작한 기록을 저장하면 이전 입력/허브로 돌아올 수 있고, 그 아래의 캘린더는 선택 날짜를 유지한다.

## 검증
- 시간 경계, 다음 식사 전 제한, 미응답 제외, 명시적 이전/이후 상태, 여러 날 반복과 단일 일자 중복 배제, 원본 근거 이동을 테스트한다.
- 실제 앱 라우터에서 선택한 과거 날짜에 식사(사진→직접 입력), 음주, 컨디션, 배변, 진료 기록이 저장되는지 검증한다. 미래 날짜 버튼과 큰 글씨도 검증한다.
