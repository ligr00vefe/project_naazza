# 사진 분석 원인별 유효성 검사

사진 분석은 실패를 하나의 빈 결과로 합치지 않고 원인 코드와 근거 출처로 분류한다.

| 범주 | 검사와 안내 |
|---|---|
| 서버 시간 초과 | 20초 지연 안내, 최대 30초 화면 대기 종료. 상품 식별 실패로 단정하지 않는다. |
| 연결·업로드·서버·요청 한도·잘못된 응답 | HTTP/SDK 오류 코드에 따른 개별 안내. 문자열에 특정 단어가 있는지로 분류하지 않는다. |
| 사진 형식·용량 | 파일 헤더 및 10MB 한도 검사. PNG/JPEG/WebP/HEIC를 구분한다. 헤더 검사는 전체 이미지 디코딩 성공을 보장하지 않는다. |
| 해상도 | PNG/JPEG의 실제 크기를 확인한다. 짧은 변 160px 미만이면서 긴 변 320px 미만이면 사전 거절한다. |
| 흐림·어두움·빛 반사 | AI의 imageQuality 판정. 확정적인 촬영 기기 검사 결과가 아니라 모델의 추정이다. |
| 음식·포장 없음, 제품 식별 실패, 제품명/영양표 판독 불가 | 모델의 failureReason과 후보 필드를 검사한다. |
| 낮은 확신·영양값 누락 | confidence 0.85 미만, 제품명 누락, 영양표 미판독, 잘못된 숫자를 검증하고 등록 후보에서 제외한다. |
| 원인 불명 | 근거가 없으면 unconfirmed로 남기고 특정 사진 결함이나 상품 미존재를 단정하지 않는다. |

사진 분석에는 상품 DB 검색이 없으므로 '일치하는 상품 없음'은 이 과정에서 확정할 수 없다. 바코드 DB 조회에서 product:null을 받은 경우와 구분한다.

서버는 diagnosis.code와 diagnosis.source를 반환한다. source는 파일·후보 검증 또는 model_assessment로 구분된다. 앱은 같은 원인이 두 번 연속 발생한 경우에도 원인 안내를 유지하고 재촬영·직접 입력을 안내한다. 새 사진 선택 시 횟수를 초기화한다.

검증: Node 원인 분류·PNG/JPEG 검증 테스트, Flutter 전체 42개 테스트, 정적 분석을 통과했다. 실제 서버에서 80×80 PNG는 약 2초 만에 HTTP 422 low_resolution으로 반환됐다. 테스트 계정과 사진은 삭제했다.

## 반복 실패 중단 (빌드 15)
- 같은 사진의 분석 요청은 오류 원인이 바뀌어도 최대 2회다.
- 이 화면에서 서버/연결/응답 문제로 2회 실패하면 다른 사진을 선택해도 추가 AI 요청을 보내지 않는다. 화면을 새로 열면 다시 시도할 수 있다.
- 제한에 도달하면 다시 분석 버튼을 숨기고 직접 입력 및 바코드 기록을 안내한다.
- 직접 입력으로 이동할 때 사진 바이트와 파일명을 전달한다. 저장 시 사진 업로드만 하고 AI를 다시 호출하지 않는다.
- 이 제한은 반복 대기를 막으며, AI 서버의 응답 지연 자체를 해결한 것으로 간주하지 않는다.
- 테스트: 원인이 달라지는 실패의 누적 제한, 재촬영으로 서버 제한 우회 방지, 두 번 시간 초과 후 버튼 제거 및 사진 전달.

## 원인별 종료 및 세션 제한 (빌드 16)
- 흐림, 어두움, 빛 반사, 영양표/제품명 판독 실패 및 상품 식별 실패는 동일 사진 재분석을 즉시 중단한다. 원인별 재촬영·직접 입력 안내와 실제 버튼을 제공한다.
- 상품 식별 실패는 이 사진에서 인식할 수 없다고 안내하며 존재하지 않는 상품이라고 단정하지 않는다. 시간 초과를 사진 문제로 단정하지 않는다.
- 서버/연결 실패는 재시도 1회만 허용한다. 실패가 두 번 누적되면 앱 세션 내 해당 사용자에 대해 5분간 추가 요청을 막는다. 요청 한도 오류는 즉시 같은 대기 제한을 적용한다. 5분 경과가 서버 복구나 한도 초기화를 보장하지는 않는다.
- 사진 바이트 기반 식별값으로 동일 사진 재선택과 화면 재진입에 의한 제한 초기화를 막는다. 새로운 사진은 사진 인식 실패 제한을 초기화하지만 서버 대기 제한은 우회하지 않는다.
- 성공한 사진은 실패 누적을 초기화한다. 직접 입력으로 사진을 넘기고 저장할 때는 AI 재호출 없이 첨부한다.
- 상태는 앱 실행 세션에 유지되며 앱 재시작 후에는 초기화된다.

## 사용자 선택을 유지하는 복구 흐름 (빌드 17, 현재 적용)
- 실패는 해당 분석 시도의 종료다. 사용자를 차단하거나 5분을 기다리게 하지 않는다.
- 사용자는 실패 횟수와 관계없이 즉시 재분석·재촬영·다른 사진 선택·직접 입력을 선택할 수 있다. 같은 사진 재선택과 화면 재진입도 허용한다.
- 20초에는 지연을 안내하고 30초에는 해당 대기를 끝낸다. 자동 반복은 하지 않는다. 사용자가 다시 분석을 누르면 새로운 시도를 시작한다.
- 첫 서버 오류는 재시도를 우선 안내한다. 사진 품질 문제는 재촬영을 추천한다. 상품 식별 실패·AI 한도 오류·반복 실패는 사진을 첨부한 직접 입력을 먼저 보여준다. 추천 외 선택지도 유지한다.
- 분석 중에도 대기 종료 및 사진 유지 직접 입력이 가능하다. 취소 후 늦은 결과/오류는 현재 화면에 반영하지 않고, 저장하지 않은 사진만 정리한다. 기존 서버 요청은 서버 시간 제한 안에서 종료된다.
- 서버의 실제 인증·파일 크기/형식·영양정보 검증은 유지한다. 앱에서 임의 사용 제한을 추가하지 않는다. AI 제공자의 실제 요청 한도는 성공을 보장할 수 없어 정확히 안내한다.
- 검증: 연속 4회 실패 후 즉시 재시도, 자동 요청 부재, 원인별 안내와 선택권 유지, 같은 사진 재선택·재진입, 대기 중 직접 입력, 취소한 요청의 늦은 오류 격리.
