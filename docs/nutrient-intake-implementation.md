# 영양 권장량 충족 현황 구현 (2026-10-20)

## 가입 및 설정
- 로그인·회원가입 화면은 승인된 기존 디자인으로 복원했다. 회원가입 입력은 아이디·비밀번호뿐이다.
- 최초 설정 순서: 관리 목표 → 추적 항목 → 내 정보(생년월일·영양 기준) → 시작하기.
- 이전 단계로 돌아가도 입력과 추적 항목 ON/OFF 선택을 유지한다. 모션 줄이기 설정을 따른다.
- 내 정보는 건너뛸 수 있으며, 기존 회원도 더보기 → 내 정보와 영양 기준에서 추가·수정·삭제한다.
- 생년월일·기준 성별·일반/임신 1·2·3기/수유 상태를 프로필에 보관한다. 권한 판단에는 사용하지 않는다.

## 실제 화면 연결
- 홈: 오늘의 영양 간단 요약, 전체 보기 → 인사이트.
- 캘린더: 선택한 날의 영양 간단 요약, 전체 보기 → 해당 날짜 영양 상세. 끼니 필터가 영양 일일 합계를 바꾸지는 않는다.
- 인사이트: 오늘의 6개 영양소 섭취량과 권장량 대비 기록률. 월별은 완료 기록 중 성분 정보가 모두 있는 날짜만 비교한다.
- 더보기: 내 정보와 영양 기준 수정.
- 기존 공복 시간과 기록 인사이트는 유지한다.

## 기준과 계산
- 보건복지부·한국영양학회 2025 KDRIs 공식 요약표의 ix, x, xii, xiii, xvi, xvii 페이지를 대조했다.
- 단백질(g), 칼슘(mg), 철(mg), 비타민 C(mg), 비타민 D(μg), 식이섬유(g) 6종을 연결했다.
- 권장섭취량이 없는 해당 영양소·연령에는 충분섭취량을 구분해 적용한다. 영아 월령·성인/소아 연령·성별 및 성인 임신기별 추가량을 구분한다.
- 임신·수유의 과거 시작/종료 이력이 없으므로 현재 설정은 오늘 기록에만 적용한다. 이 상태에서는 월별 비교를 제공하지 않는다. 만 19세 미만의 임신·수유 기준을 임의 적용하지 않는다.
- 공개 성분표의 기준량 × 실제 섭취량 비율로 계산한다. 소분·개수는 이미 반영된 실제 섭취량을 한 번만 사용한다. g과 ml를 임의 환산하지 않는다.
- 이전 식사와 이름이 같다는 이유로 영양값을 가져오지 않는다. 원재료명만으로 영양소를 만들어내지 않는다.
- 직접 입력한 열량만 있으면 기타 영양소는 미확인이다. 데이터의 누락과 실제 0을 구분한다.
- 음식 이름·양·열량을 직접 수정하면 이전 분석 상세를 재사용하지 않는다.

## 충족 및 기록 완료
- 과섭취·상한 초과·결핍 경고 기능은 추가하지 않았다.
- 식사 기록을 완료했고, 해당 영양소의 정보가 모든 음식에 있으며, 합계가 목표 이상이면 ‘충족’으로 표시한다.
- 그 외에는 확인된 값의 비율(진행 막대 최대 100%)과 정보 누락을 보여준다. 미확인을 0으로 계산하지 않는다.
- 완료 확인은 식사 기록 상세에 64자리 SHA-256 지문으로 저장한다. 음식 추가·삭제·시간/양/영양값 변경 시 지문이 달라져 재확인을 받는다. 메모만 바꾼 경우에는 유지된다.
- 월별 분모는 성분마다 다를 수 있다. 미기록일과 성분이 빠진 날짜를 분모에 넣지 않는다.

## API 키
현재 6종 충족 현황에는 추가 키가 필요 없다. 이미 연결된 전국통합식품영양성분정보 API와 기록에 저장된 영양 정보로 계산한다. 기준표 및 집계에는 식품 API 추가 호출이 없다. 프로필/기록 완료 저장은 기존 Supabase 요청이다.

- 현재 영양정보 API: https://www.data.go.kr/data/15100064/standard.do
- 공식 기준표 배포·정오표: https://www.kns.or.kr/fileroom/fileroom_view.asp?BoardID=Kdr&idx=167
- 추후 아미노산 확장을 위한 선택 후보 USDA 키 발급(현재 미연결·이번 작업에 불필요): https://fdc.nal.usda.gov/api-key-signup/

새 화면을 위해 원재료 API나 USDA API를 추가 호출하지 않는다. 공공데이터에 제품/성분이 없는 경우 이 기능도 값을 보완해 만들지 않는다.

## 검증
생일 경계·성별/연령대·임신기별 기준, 영아 충분섭취량, 단위 불일치, 소분 및 개수, 미확인/0 구분, 완료 지문 변경, 2배 글씨 UI, 월별 충족 집계를 검사한다. 실제 Supabase SDK로 프로필 기준 재로그인 보존과 영양 출처·완료 지문 저장 및 재조회도 확인했다.
# 추가 영양소 및 물 배너 (2026-10-20)

- 기존 6종 외 칼륨, 인, 비타민 A(μg RAE), B1, B2, 니아신을 추가했다.
- 공식 15100064 API의 k/p/vitaRae/thia/ribf/nia 필드만 사용한다. 추가 키/추가 호출은 없다.
- 2025 KDRIs 공식 요약표 xii/xiii/xvi의 연령·성별 기준과 임신/수유 부가량을 적용한다.
- 니아신 API는 mg, 기준은 mg NE이고 트립토판을 제공하지 않는다. 니아신 함량과 기준은 보여주되 충족률 및 월별 충족 판정은 제외한다.
- 기존 식사에 저장된 원본 nutrition_source에 새 값이 없으면 미확인으로 남긴다. 같은 이름의 다른 음식이나 이전 기록으로 보충하지 않는다.
- 기존 6종은 기본 표시, 추가 6종은 펼치기로 표시하여 화면 길이를 줄인다.
- 현 API에 없는 마그네슘/아연/엽산/B6/B12/E/K/콜린/아미노산/지방산 등의 자동 섭취 합산은 지원하지 않는다. 기준표 존재와 실제 함량 확보는 구분한다.
- 인사이트 하단 배너는 기존 로컬 이미지 assets/images/hydration_mint_blue.png와 '하루 물 7~8컵' 한 문장만 표시한다. 독려 및 부연 문구는 제거했다. 이후 사용자 추가 요청에 따라 별도의 물 마시기 기록 페이지와 DB 저장을 추가했다. 자세한 내용은 [물 마시기 기록](water-records.md)을 따른다.
- 컵 수는 정책브리핑의 성인 일반 안내를 따른다. 개인별 계산값이나 KDRIs의 총수분을 물 섭취량으로 환산한 값은 아니다. 출처: https://www.korea.kr/news/policyNewsView.do?newsId=148829504 (원문 한 컵 200cc). 앱에는 ml/cc 수치를 표시하지 않는다.
