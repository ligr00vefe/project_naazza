# 식사 시각·공복 평균·배변/변비 기록 (앱23)

2026-10-15

- 식사 카테고리(아침/점심/저녁/간식/기타)는 유지하며 날짜·시각 선택을 직접 입력/사진 기록/수정에 추가했다. 기존 meals.eaten_at 필드에 UTC로 저장하고 앱에는 현지 시각으로 표시한다. 과거 시각을 임의로 재해석하거나 일괄 수정하지 않았다. 이전 기록은 실제 식사 시각 대신 등록 시각이 저장돼 있을 수 있으므로 필요한 기록은 수정해야 한다.
- 공복은 기록 기반 식사 간격이다. 사용자별·현지 달력 날짜별 meal 기록을 정렬하고 정확히 연속된 날짜에서 전날 마지막과 다음 날 첫 기록 차이만 계산한다. 끼니 카테고리로 순서를 추정하지 않고 간식도 포함한다. 기록 빠진 날짜는 연결하거나0으로 채우지 않는다. 누락된 섭취를 알아낼 수는 없다.
- 월/연도 귀속은 공복이 끝나는 다음 날 첫 기록의 날짜로 한다. 9/30→10/1은10월이다. 월평균은 해당 구간 총시간/실제구간수, 연평균도 전체구간 가중 평균이다(월평균의 단순 평균 아님). 월별 화면은 구간별 시간, 연도별 화면은 월별 평균과 횟수를 보여준다. 구간0개는 미확인으로 표시한다.
- 모든 기록 API를 사용자별500행 페이지로 읽도록 보완하여 연간 기록이1000행 기본 제한에 잘리지 않게 했다.
- 배변은 기존에도 하루 다회 등록 가능했다. 이제 날짜·시각을 선택한다. 배변했어요/변비·배변 못함을 구분하고 배변했어도 변비가 있었다는 표시를 할 수 있다.
- bowel_logs.had_bowel_movement/constipation을 추가했다. 실제 배변일 때만 bristol_type이 필요하고 배변 못함이면null이다. 기존 기록은 실제 배변true/변비false를 기본값으로 유지한다. 기존 RLS/사용자 소유권은 유지한다. 변비·배변 못함은 실제 배변 횟수/형태 평균에 섞지 않는다.
- 서버 이력과 로컬 마이그레이션의 과거 타임스탬프가 달라 migration fetch로 실제 적용본을 복구했다. 과거 사본은 migration-archive에 보존했고 서버 이력을 되돌리거나 과거 SQL을 다시 적용하지 않았다. 새 변비 마이그레이션만 dry-run 확인 후 적용했다.

검증: 공복 연속8일/7구간, 간식 우선, 누락일/사용자 분리, 월경계, 연간 가중평균, 데이터 없음, 월/연도 필터, 같은 날 배변·변비2건과 시각을 테스트했다. 실제 SDK에서 식사 시각 왕복, 같은 날2개 배변 상태, 형식null 허용, 전체3개 기록 조회까지 확인했고 QA 계정/세션을 정리했다. 실제 휴대폰 화면은 APK 설치 후 확인해야 한다.
