# 무료 운영을 위한 사진 로컬 보관 전환안

2026-10-15. 현재 구현은 Supabase Storage meals에 사진을 영구 저장하며 DB에는 경로를 저장한다. Free의 DB500MB와 파일Storage1GB는 별도 한도다(https://supabase.com/pricing). 현재 구조는 장기/다중 사용자 운영에서 누적되므로 개선이 필요하다.

전환 대상:
1. 촬영/직접 입력 사진은 휴대폰 앱 전용 파일 저장소에 보관하고 DB에는 로컬 식별자만 저장. 조회는 해당 폰의 파일에서 표시.
2. AI 분석은 인증된 Edge Function에 이미지 바이트를 직접 전송하고 Storage 영구 업로드를 제거. API키는 서버 전용 유지. 파일 형식/크기/분석 기한 검증 유지.
3. 새 사진을 저장하는 경로(사진 분석 저장/직접 입력/수정) 모두 전환. 기록 삭제 시 해당 로컬 파일 정리.
4. 기존 서버 사진은 해당 사용자 폰에 다운로드하여 무결성과 상세 표시를 확인한 뒤에만 서버 제거. 확인되지 않은 파일을 일괄 삭제하지 않음. 사진 없이 기록을 유지해야 하는 다른 기기는 사진이 이 폰에 있다는 안내 필요.
5. 로컬 사진은 원재료 캐시처럼 7일 만료하지 않음. 사진은 영구 기록 첨부물이며 사용자 삭제/백업 정책을 따른다.

결정할 사용자 동작: 휴대폰만 저장하면 사진은 다른 폰에 동기화되지 않고 앱 데이터 삭제/기기 분실 시 로컬 보관분 복구를 위한 별도 내보내기/백업이 필요하다. 개인 무료 운영을 위해 로컬+사용자 백업 방식을 우선 후보로 제시한다. 사진의 기기간 동기화가 필요하면 별도 무료 개인 백업 저장소 연동이 필요하다.

현재 상태: 설계 점검 완료. 로컬 전환 코드/분석 요청 변경/기존 이미지 이동/삭제는 아직 수행하지 않았다.

사용자는 이후 서버 보관 유지를 선택했다. 이 로컬 전환안은 진행하지 않으며 현재 사진은 Storage/DB경로 방식으로 유지한다.
