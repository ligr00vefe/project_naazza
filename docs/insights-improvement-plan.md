# 인사이트 개선 기획

현재 ‘기록 활동’은 기록 여부만이 아니라 날짜별 등록 건수를 보여주는 차트다.
음식 하나를 한 기록으로 저장하면 건수가 커져 실제 끼니 수와는 다르다.
현재 화면에서는 이름을 ‘기록 횟수’로 바꿔 의미를 분명히 한다.

## 우선 구현할 내용 분석

1. **하루 섭취 열량**: 날짜별 누적 막대, 아침·점심·저녁·간식·기타를 색과 텍스트로 구분.
   날짜를 누르면 끼니별 총열량과 음식 상세로 이동. 세로축 kcal, 가로축 날짜.
   열량 미입력은 0 kcal로 해석하지 않고 ‘열량 미기록 음식 N개’를 별도 표시.
   식사 없는 날은 ‘기록 없음’으로 표시하고 실제로 안 먹었다고 판단하지 않는다.
2. **배변 패턴**: 날짜별 배변 횟수 막대 + 형태 분포 + 복통 기록 횟수.
   형태 1~7을 단순 평균 하나로 보여주지 않고 ‘단단함·형태 있음·무름’ 분포와 짧은 문구로 표시.
   날짜를 누르면 시간, 형태, 통증, 긴급도, 양, 메모를 확인한다.
3. **컨디션 변화**: 날짜별 증상 표시와 복통·피로 등 증상별 빈도 막대.
   ‘이상 없음’, ‘상태 미확인’, ‘기록 없음’을 구분한다.
   심한 정도의 추세는 아직 입력 데이터가 없으므로 먼저 선택형 강도 입력과 저장 구조를 마련해야 한다.
4. **진료 일정**: 실제 검진·문진·방문한 날과 다음 진료일을 별도 표시.
   기관·진료과·방문 구분·검사·메모·처방 변경 사실을 상세에서 확인한다.

## 다음 단계

음식 태그와 이후 증상이 함께 나타나는 빈도를 시간 구간별로 비교한다.
표본 수와 기록 기간을 함께 보여주고, 원인이라고 단정하거나 질병을 진단하지 않는다.
같은 날의 반복 등록은 음식 건수·끼니 수를 각각 계산해 중복 해석을 막는다.

## 공통 사용 방식 및 검증

최근 7·30·90일 선택, 스크롤 가능한 날짜 축, 값과 단위를 제공한다.
그래프를 누르면 정확한 값과 상세 기록을 보여주고 큰 글씨에서도 레이아웃이 늘어나도록 한다.
그래프 설명을 화면 읽기 도구에 제공한다.
현지 날짜로 집계하고 누락, 시간대 경계, 반복 간식, 기록 수정·삭제, 빈 기간을 테스트한다.
이번 작업은 화면 오류 수정과 위 기획 작성까지이며 위 내용 그래프는 후속 구현 범위다.
